# Arrowhead EC-i Homebridge plugin design

Build a native CommonJS Homebridge platform for HOOBS and Apple Home. No Home Assistant, cloud account or Python runtime is required. Initial scope is single-area EC-i installations using MODE 4 and Serial over IP. The arm/disarm commands affect the whole panel; multi-area installations are explicitly unsupported in this experimental release. Controls default off. Motion zones are manually named and numbered.

Architecture: a standalone TCP client parses newline-delimited events, serializes command transactions, negotiates MODE 4 and refreshes STATUS. It emits state and availability events and reconnects with backoff. A Homebridge adapter maps confirmed state to SecuritySystem and configured zones to MotionSensor or ContactSensor. Unknown/stale state must return a HomeKit communication error, never default to disarmed. Disconnects invalidate all state; commands are never replayed after reconnect. A command acknowledgement means accepted, not final state. PINs and raw commands are never logged.

Target Node >=20, Homebridge >=1.8.4 <3. No production dependencies. Verify with the real Homebridge 1.8.4 HAP API and the current Homebridge line. Runtime compatibility is distinct from live HOOBS/panel validation. Publish as MIT with upstream attribution. Public experimental release must clearly state no real panel has been tested.

Client interface: new ArrowheadClient({host,port=9000,area=1,commandTimeoutMs=5000,reconnectDelayMs=1000,heartbeatMs=30000,staleTimeoutMs=90000}). EventEmitter emits 'state' and 'availability'. Properties: connected boolean; state = {mode: 'unknown'|'disarmed'|'away'|'home', alarm:boolean, zones:Map<number,boolean>, batteryLow:boolean|null, tamper:boolean|null, mainsFault:boolean|null, pending:null|'away'|'home'}. start():void, stop():void, async control(target,userNumber,pin):Promise<void> where target is 'away','home','disarmed'. Unknown zone state remains absent. Alarm state derived from ZA/ZR; D clears active alarm state. Only known incoming state is surfaced. Client never emits Node's unhandled 'error' event. Adapter supplies read-only controls policy and validates configuration and credentials.

Tests: real local TCP simulator exercises fragmentation, interleaved events/ACKs, startup, disconnect/reset, reconnect, timeouts, commands and no command replay. HAP tests cover actual services, current/target distinction, read-only rejection, missing/invalid credentials, unavailable state, sensor mapping and accessory caching. Public release includes packaged tarball for manual installation; npm listing requires separately authenticated npm publishing.
